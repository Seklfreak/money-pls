# Money pls — working notes

- Project is generated by xcodegen from `project.yml`; never edit the .xcodeproj. `Config/Secrets.xcconfig` is
  gitignored (team ID + Sentry DSN; copy from `Secrets.example.xcconfig`; `//` is a comment in xcconfig, so URLs
  need the `https:/$()/` split). Versions come from `MARKETING_VERSION`/`CURRENT_PROJECT_VERSION` via `$(…)` —
  never literal versions in the plist properties. Release signing is manual and scoped to the app target in
  `project.yml` (CLI signing settings would hit the Sentry SPM target, which refuses profiles). Resources are folder references
  (fonts) — a leftover top-level `Resources/` dir inside the built .app makes CFBundle report no bundle ID
  ("Missing bundle ID" on install): `rm -rf` the built .app and rebuild.
- Parser rules and why they exist are documented inline in `ReceiptParser.swift`; the harness with the four reference
  photos lives in `~/workspace/money-pls-lab` (macOS, same frameworks). Run new receipts through it first.
- Simulator: install with an explicit UDID on an iOS 26.5 runtime; drive with AXe (`axe describe-ui`, coordinates are
  points, not screenshot pixels); parse logs need `log show --info`.
- Parsing runs in a detached task on purpose — a view-bound `.task` gets cancelled when the cover re-identifies and
  Vision surfaces that as `requestCancelled`.
- Public repo: no homelab/cluster details, no personal data, no test receipt photos in git.
- Shipping: same pipeline as Moodring (Test → ai-release-action → TestFlight). The TestFlight job is gated on the
  `APP_STORE_CONNECT_KEY_ID` secret; set it only once the App Store Connect app record for
  `dev.winktech.moneypls` exists, or the upload step fails red. Bundle ID and the "Money pls App Store" profile were
  created via the ASC API; Sentry project is `winktech/money-pls-ios`.
